# zen-type 設定頁面 UI 方案比較報告

**產生時間**：2026-04-19 11:27
**專案**：zen-type
**背景**：目前設定頁用瀏覽器 + HTTP server（`http://127.0.0.1:7878`）呈現；使用者想評估「純視窗」的替代方案。

## 逐項詳解

### ① 瀏覽器 + HTTP server（目前方案）

**運作方式**：Python 內嵌 `http.server` 監聽 `127.0.0.1`，HTML 檔為前端，透過 `/api/config` REST 操作。

- ✅ **零額外依賴**（用 Python stdlib）
- ✅ HTML/CSS/JS 生態最大，版面調整最快
- ✅ 任何裝置都能遠端連（本機、手機都可）
- ✅ 打包時只需 bundle 一個 `.html`
- ❌ 要開瀏覽器分頁，使用者覺得「不像 App」
- ❌ 瀏覽器快取可能干擾
- ❌ 需要占用 port（若 7878 被占則需處理）
- ❌ 不能用 OS 原生對話框（資料夾選擇器等）

**適合**：已實作完成；維持現狀最省功。

---

### ② pywebview（**強烈推薦**）

**運作方式**：沿用既有 HTML，但用 `pywebview` 把它塞進一個原生視窗，內部用系統 WebView（Windows：WebView2 / macOS：WKWebView）。**無須瀏覽器、無須 port、無須 HTTP server**。

```python
import webview
webview.create_window("zen-type 設定", html=html_content, width=900, height=700)
webview.start()
```

- ✅ **看起來就是原生 App**（視窗、icon、工作列）
- ✅ 保留現有 HTML/CSS/JS 投資（幾乎不用改）
- ✅ 可與 Python 雙向呼叫（`window.api.save_config(data)` ↔ Python）
- ✅ 無 port、無瀏覽器依賴
- ✅ 可用 OS 原生檔案對話框
- ✅ 打包後體積增加有限（~2MB），Windows 10/11 內建 WebView2
- ⚠️ 需使用者電腦有 WebView2 執行期（Win11 內建；Win10 需手動/安裝器帶）
- ⚠️ 某些瀏覽器 CSS 極新特性可能略有差異

**遷移成本**：**極低**。把 `ui/settings.html` 丟給 pywebview 即可，REST API 改為直接呼叫 Python 函式。

**綜合**：**最佳升級路徑**，兼顧現代外觀與既有投資。

---

### ③ Tkinter（Python 標準庫）

**運作方式**：stdlib 內建的 Tk 綁定，`ttk` 提供較現代的 theme。

```python
import tkinter as tk
from tkinter import ttk
root = tk.Tk()
ttk.Label(root, text="Groq API Key").grid(row=0, column=0)
ttk.Entry(root).grid(row=0, column=1)
root.mainloop()
```

- ✅ **零依賴**（stdlib 內建）
- ✅ 打包後不會增加多少大小
- ✅ 文件豐富、AI 熟悉度高
- ❌ 預設外觀復古（像 Windows XP），調整深色主題需自己刻
- ❌ 排版系統（pack/grid/place）較原始，稍複雜介面會很繁瑣
- ❌ 無內建下拉動畫、Toast 等現代元件

**適合**：純本地小工具、不在乎美感時。

---

### ④ CustomTkinter（**若堅持純視窗的第二推薦**）

**運作方式**：第三方套件，包裝 Tkinter 但提供現代外觀（圓角、深色、色彩系統）。

```python
import customtkinter as ctk
ctk.set_appearance_mode("dark")
ctk.set_default_color_theme("blue")
app = ctk.CTk()
ctk.CTkEntry(app, placeholder_text="API Key").pack(pady=10)
app.mainloop()
```

- ✅ 外觀**現代、深色、看起來很像 zen-type 目前的 HTML**
- ✅ API 與 Tkinter 相容，學習曲線低
- ✅ 打包後體積小（< 5 MB 增幅）
- ✅ 繁體中文顯示無問題
- ❌ 元件庫有限（沒有 PyQt 豐富）
- ❌ 開發者是單人維護，長期穩定性待觀察
- ❌ 排版仍是 pack/grid 系統，不如 Web CSS 自由

**適合**：想要純視窗、外觀現代、不想學新框架。

---

### ⑤ PyQt6 / PySide6

**運作方式**：Qt 框架的 Python 綁定。PySide6 由 Qt 官方維護（LGPL，商用友善）；PyQt6 由 Riverbank Computing 維護（GPL/商用雙授權）。

- ✅ **業界最成熟**、元件最豐富（樹狀、表格、docking、樣式表）
- ✅ QSS（類 CSS 樣式表）可做出任意外觀
- ✅ Qt Designer 所見即所得拖拉介面設計
- ✅ 官方文件紮實、StackOverflow 解答最多
- ❌ **打包後很大**（最小 ~60 MB，含 Qt DLL）
- ❌ 學習曲線中等，訊號槽機制需適應
- ❌ 授權較複雜（PyQt6 為 GPL，靜態連結會傳染）
- ❌ Python 啟動速度明顯變慢（Qt 初始化 1~2 秒）

**適合**：大型桌面應用、已經熟悉 Qt 的開發者。本專案而言**過度殺雞**。

---

### ⑥ Dear PyGui

**運作方式**：GPU 加速的 immediate-mode GUI（遊戲業界常見），底層用 DearImGui。

- ✅ **效能極佳**（60fps 即時重繪）
- ✅ 繪製自訂圖表、即時波形很方便（可顯示音量計！）
- ✅ 打包大小中等
- ❌ 外觀**偏遊戲除錯工具風**，不像傳統 App
- ❌ 生態小、文件較少
- ❌ Immediate-mode 思維與大部分教程不同

**適合**：若你想在設定頁顯示**即時音量波形**或**錄音前預覽音量**，Dear PyGui 很合。否則無必要。

---

### ⑦ Flet（Flutter for Python）

**運作方式**：用 Flutter 渲染引擎，Python 寫 widget 樹；可輸出桌面視窗、Web、手機。

```python
import flet as ft
def main(page: ft.Page):
    page.add(ft.TextField(label="Groq API Key"))
ft.app(target=main)
```

- ✅ **Material Design 現代外觀**
- ✅ 一套程式同時支援桌面/Web/手機
- ✅ 熱重載、開發體驗好
- ❌ Flutter 引擎體積大（~40 MB）
- ❌ 仍在快速演化，API 偶有破壞性變更
- ❌ 中文社群資源少

**適合**：未來計畫做手機版；若只要 Windows 桌面，**C/P 比不如 ②**。

---

### ⑧ wxPython

**運作方式**：wxWidgets 的 Python 綁定，呼叫 OS 原生元件。

- ✅ **真正的原生 OS 外觀**（Windows 看起來就像 Windows 應用）
- ✅ 元件完整
- ❌ 外觀「太原生」，跨平台一致性差，且不符合 zen-type 現代風格
- ❌ 打包不如 Qt 順
- ❌ 文件/教材較過時

**適合**：想做出「微軟內建風格」的工具程式。與 zen-type 品味不符。

---

### ⑨ Toga（BeeWare 專案）

**運作方式**：真正跨平台原生（Windows/macOS/Linux/iOS/Android）。

- ✅ 跨平台原生外觀、BeeWare 整個工具鏈完整
- ✅ MIT 授權、官方維護
- ❌ **仍在 beta**，Windows 支援成熟度不如 Qt/Tk
- ❌ 元件庫還在擴充
- ❌ 打包雖有 Briefcase 工具，但新手不易

**適合**：想投注於 BeeWare 生態、預期未來上架 iOS/Android。

---

### ⑩ Windows Forms（pythonnet）

**運作方式**：透過 `pythonnet` 橋接到 .NET，直接用 `System.Windows.Forms`。

- ✅ 最正統的 Windows 外觀
- ✅ Visual Studio 的 WinForms Designer 可用
- ❌ 只支援 Windows
- ❌ 打包要 bundle .NET runtime（或假設已裝）
- ❌ Python 生態少用、教材罕見

**適合**：只做 Windows 內部工具、開發者熟悉 C#/.NET。對本專案意義不大。

---

### ⑪ TUI（Textual / Rich）

**運作方式**：在終端機裡做互動式介面，Textual 更進一步支援滑鼠、動畫、滾動。

- ✅ **無視窗系統依賴**（SSH、Docker、伺服器都能用）
- ✅ 外觀意外地現代（Textual 的 TCSS 很像 CSS）
- ✅ 打包超小
- ❌ 使用者要習慣鍵盤操作
- ❌ 與 tray-app 體感不符（要先開終端機）
- ❌ 部分人會覺得「工程師才會用」

**適合**：開發者工具、CLI 為主的軟體。zen-type 是給一般使用者，不合適。

## 「保留 HTML」vs「改寫 UI」決策樹

```
你願意改寫設定頁嗎？
├── 不願意（想保留 HTML/CSS/JS 成果）
│   └── ② pywebview ← 最佳選擇
│
└── 願意改寫
    ├── 要體積小？ → ④ CustomTkinter
    ├── 要外觀最漂亮？ → ⑤ PyQt6
    ├── 要跨平台手機？ → ⑦ Flet
    └── 要極簡工具？ → ③ Tkinter
```

## 對 zen-type 的建議

### 方案 A：**切換到 pywebview**（強推）

- 工程成本：**半天**（幾乎不改 HTML，把 HTTP 呼叫改為 `pywebview.api`）
- 使用者體驗：**大幅提升**（像原生 App，不用看到瀏覽器）
- 打包體積：僅增加 ~2 MB
- 風險：需 Windows 10/11 有 WebView2（Win11 內建，Win10 絕大多數用戶已裝）

**遷移要點**：

```python
# 新增 ui/native_window.py
import webview
from zen_type.config.settings import Settings

class SettingsApi:
    def __init__(self, settings: Settings):
        self.settings = settings
    def get_config(self): return self.settings.load()
    def save_config(self, cfg): self.settings.save(cfg); return {"ok": True}

def open_settings(settings):
    api = SettingsApi(settings)
    html_path = Path(__file__).parent / "settings.html"
    webview.create_window(
        "zen-type 設定", url=str(html_path),
        js_api=api, width=960, height=720,
    )
    webview.start()
```

HTML 端只要把：
```javascript
await fetch("/api/config")
```
改成：
```javascript
await window.pywebview.api.get_config()
```

---

### 方案 B：完全改用 CustomTkinter

- 工程成本：**2~3 天**（重寫所有 UI）
- 優勢：零網路、零瀏覽器依賴、純 Python
- 劣勢：丟棄既有 HTML、版面調整靈活度下降
- 打包小、依賴簡單

---

### 方案 C：兩者並行（最彈性但工）

- 保留 HTTP server（讓手機、另一台電腦也能連入設定）
- 同時加 pywebview 視窗給一般使用者
- 托盤選單提供兩個選項「開啟設定視窗 / 在瀏覽器開啟」

---

## 總結

| 情境 | 推薦方案 |
|---|---|
| **最少工、最大體驗提升** | ② pywebview |
| **想脫離 Web 技術、純 Python GUI** | ④ CustomTkinter |
| **做大應用程式、不介意體積** | ⑤ PyQt6/PySide6 |
| **要兼顧遠端存取與本地體驗** | ① + ② 並行 |
| **目前階段先不動** | 維持 ①（你已驗證可用） |

**個人建議**：升級到 ② **pywebview**。花半天、視覺體驗脫胎換骨、既有 HTML 全部保留。
