**目的**：比較所有可行的發佈與執行方式，協助決定打包策略

## 比較總表

| 方式 | 檔案產物 | 使用者門檻 | 啟動速度 | 分發大小 | 更新方便度 | 優點 | 缺點 |
|---|---|---|---|---|---|---|---|
| **① `uv run zen-type`（目前）** | 只需原始碼 + venv | 需懂 uv | 快（~1s） | 源碼 + venv（~200MB） | 極佳（改碼即生效） | 最輕量、除錯最直接 | 使用者要先裝 uv/Python |
| **② `start.bat`** | 雙擊 .bat | 低（已裝 uv） | 快 | 同上 | 極佳 | 一鍵啟動、保留 uv 的依賴管理 | 仍需 Python + uv |

| **④ PyInstaller --onefile** | 單一 `zen-type.exe` | 零門檻 | 稍慢（首次 3–5s 解壓到 temp） | 約 80–120 MB（單檔） | 需重新打包 | **最方便分發**、一檔走遍 | 首啟較慢、某些防毒誤判高 |
| **⑤ pipx install** | 無 exe，但 `zen-type` 命令可用 | 需 pipx | 快 | ~200MB | pipx upgrade 即可 | 跨專案命令乾淨；適合懂 Python 使用者 | 仍需 Python |
| **⑥ Nuitka onefile** | 單 exe（原生編譯） | 零門檻 | 非常快（~1s） | 60–100 MB | 需重新打包 | 啟動最快、不易逆向 | 編譯慢、生態較小、偶有相容問題 |
| **⑦ Windows Shortcut (.lnk)** | 桌面/開始功能表捷徑 | 零（但需先用①或②） | 依底層方式 | 幾 KB | 同底層 | 最像「app」的使用者體驗 | 只是啟動器，不解決分發 |
| **⑧ 註冊開機啟動** | 寫 HKCU Run | 零 | 登入時自動啟動 | 0 額外 | 同底層 | 真常駐 | 只管啟動，不管安裝 |
| **⑨ MSI/Installer（Inno Setup、NSIS）** | `zen-type-setup.exe` | 零 | 快（裝後同 ③/④） | 依內容物 | 需重打 | 最正式、含開始功能表圖示、解除安裝 | 製作繁瑣 |
| **⑩ Microsoft Store / winget** | store/winget 安裝 | 零 | 快 | 依上架版本 | 自動更新 | 最無痛更新 | 需申請帳號/審核，最複雜 |

## 關鍵決策點

### 單檔 vs 資料夾（onefile vs onedir）

- **onefile 優勢**：一個 `.exe` 帶著走，使用者心理門檻最低
- **onefile 劣勢**：
  - 首次啟動要解壓縮到 `%TEMP%\_MEIxxxxxx`（約 3–5 秒）
  - 某些防毒誤判率較高（因打包器簽章）
  - 被防毒鎖檔時會啟動失敗
- **onedir 優勢**：啟動快（直接讀檔）、更新只需替換單一 pyd/dll
- **onedir 劣勢**：資料夾內一堆檔案，使用者看起來「亂」，分發前通常要壓縮

### Console vs Windowed

- **有 console（console=True）**：黑視窗顯示 log；除錯方便，但使用者視覺上會多一個視窗
- **無 console（--noconsole / windowed）**：乾淨但看不到 log；出錯難除錯
- **常見做法**：**兩種都建**
  - `zen-type.exe`（無 console）— 日常使用
  - `zen-type-debug.exe`（有 console）— 出問題時執行

### PyInstaller vs Nuitka

| 項目 | PyInstaller | Nuitka |
|---|---|---|
| 成熟度 | 非常高 | 中等 |
| 打包速度 | 快（30 秒–2 分鐘） | 慢（5–15 分鐘，需編譯） |
| 啟動速度 | 中 | 快（原生機器碼） |
| 產物大小 | 大 | 稍小 |
| 相容性（特殊套件如 sounddevice） | 高 | 偶有問題 |
| 社群資源 | 多 | 少 |
| 建議對象 | **本專案** | 追求極致效能 |

## 針對 zen-type 的特殊考量

1. **`keyboard` 套件需管理員權限**
   某些按鍵（如 CapsLock）的 suppress 行為在非管理員模式下可能失效；onedir/onefile 都有此限制，與打包方式無關。

2. **`sounddevice` 需要 PortAudio DLL**
   PyInstaller 會自動抓 `libportaudio.dll` 等共享函式庫，但需驗證打包後能正常錄音。

3. **`settings.html` 是資料檔**
   必須用 `--add-data "src/zen_type/ui/settings.html;zen_type/ui"` 納入，且程式碼要能處理 `sys._MEIPASS` 路徑（PyInstaller 執行期臨時解壓路徑）。

4. **Tray 圖示與應用圖示**
   - 托盤圖示（`tray_icons.py`）用 Pillow 動態生成，**不需要** asset
   - 應用 exe 圖示（`.ico`）需另外準備，用 PyInstaller `--icon` 參數指定

5. **防毒誤判風險**
   PyInstaller 打包的 exe 被 Defender 或其他防毒軟體誤判的機率較高，正式分發前建議：
   - 代碼簽章（code signing，約每年 $100–400 USD）
   - 上傳 VirusTotal 先驗
   - 或接受使用者會看到 SmartScreen 警告

## 本專案建議方案（結合「兩版本 + PyInstaller」選擇）

```
dist/
├── zen-type/                    ← onedir 版（正常使用、啟動快）
│   ├── zen-type.exe             ← 無 console，雙擊啟動
│   ├── zen-type-debug.exe       ← 有 console，除錯用
│   └── _internal/...            ← DLL 與資源
└── zen-type-portable.zip        ← 將 onedir 壓縮，方便分發
```

### 實作藍圖

1. 新增 `build.py`：驅動 PyInstaller 的腳本（雙 exe + zip）
2. 新增 `build.bat`：一鍵 `uv run python build.py`
3. 在 `pyproject.toml` 加 `[project.optional-dependencies] build = ["pyinstaller>=6.0"]`
4. 在 `settings_server.py` 加 `_resource_path()` 處理 `sys._MEIPASS`
5. 可選：準備 `assets/icon.ico` 作為 exe 圖示
