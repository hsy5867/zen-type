# 修復「右鍵開啟設定」於打包 exe 失效

## Context

`zen-type-0.2.0.exe`（PyInstaller --onefile + --noconsole 打包）執行後，於系統匣
圖示按右鍵選「開啟設定」時設定視窗不會出現。在原始碼模式（`uv run python -m zen_type.app`）
卻可正常開啟，代表問題只發生在凍結後的子行程中。

目前的流程（[src/zen_type/app.py:107-146](src/zen_type/app.py)）是用
`subprocess.Popen([sys.executable, "--settings-window", ...], creationflags=CREATE_NO_WINDOW)`
重新啟動同一支 exe，子行程中由 [src/zen_type/app.py:254](src/zen_type/app.py)
分流到 [src/zen_type/settings_window.py:141](src/zen_type/settings_window.py) 開
pywebview 視窗。

當前看不出真正失敗原因有兩個結構性原因：

1. **沒有檔案層級 log**——`logging.basicConfig` 只寫 stderr，但 `--noconsole`
   讓 stderr 被丟掉。
2. **子行程的 stdout/stderr 沒被父行程 pipe**——`Popen` 沒有 `stdout=` 或
   `stderr=`，再加上 `CREATE_NO_WINDOW`，子行程任何錯誤訊息都看不到。

最可能的根因（待 log 確認）：

- **HTML_PATH 在凍結子行程解析錯誤**——
  [src/zen_type/settings_window.py:23](src/zen_type/settings_window.py)
  使用 `Path(__file__).resolve().parent / "ui" / "settings.html"`，在 PyInstaller
  onefile 中 `__file__` 不一定能對到實際解壓後 `_MEIPASS/zen_type/ui/settings.html`
  的位置。失敗時行 157-159 會 silently `return 1`。
- **WebView2 Runtime 缺失**——pywebview 在 Windows 預設後端是 Edge WebView2，
  使用者機器若沒裝 Microsoft Edge WebView2 Runtime，建立 webview 時直接 throw，
  exit code 非 0，但 user 看不到任何訊息。
- **打包時 settings.html 真的沒進去**——build.py 看起來有加，但可保險檢查解壓後
  的 `_MEIPASS\zen_type\ui\settings.html` 是否真的存在。

## 修復策略：先加診斷、再對症下藥

不直接賭單一原因。先讓任何失敗都會留下證據，再依 log 套用最終修復。

### 步驟 1：加上檔案層級的全域 log

**檔案：[src/zen_type/app.py](src/zen_type/app.py) 與
[src/zen_type/settings_window.py](src/zen_type/settings_window.py)**

把 `logging.basicConfig` 改成同時寫 stderr 和檔案。檔案放在使用者可寫處，例如
`Settings.path.parent / "zen-type.log"`（與 config.json 同目錄，`%APPDATA%\zen-type\`）。
父子兩個程序都用同一個 log 檔（用 append mode）。

實作要點：
- 抽一個小 helper（比如 `zen_type/core/logfile.py`）回傳一個 `RotatingFileHandler`
  或單純 `FileHandler`，讓 `app.py:main()` 和 `settings_window.py:main()` 都呼叫。
- 父子分別寫 `[parent]` / `[settings-child]` 前綴，方便對照。

### 步驟 2：捕捉子行程 stdout/stderr 到 log 檔

**檔案：[src/zen_type/app.py:138-140](src/zen_type/app.py)**

把 `subprocess.Popen(cmd, creationflags=creationflags)` 改成：

- 開啟（append）log 檔當 stdout 與 stderr 的 fd
- 即便子行程在 `webview.start()` 之前就崩潰，traceback 都會落地到 log

這樣使用者下次按「開啟設定」失敗時，`%APPDATA%\zen-type\zen-type.log` 會直接告
訴我們是哪一行噴錯。

### 步驟 3：強化 HTML_PATH 解析（防呆）

**檔案：[src/zen_type/settings_window.py:23](src/zen_type/settings_window.py)**

把單一行常數改成函式，明確處理 frozen 情境：

```
def _resolve_html_path() -> Path:
    base = Path(getattr(sys, "_MEIPASS", None) or Path(__file__).resolve().parent.parent)
    # frozen: <_MEIPASS>/zen_type/ui/settings.html
    # source: <repo>/src/zen_type/ui/settings.html
    return base / "zen_type" / "ui" / "settings.html"
```

並把 line 157-159 的「missing → return 1」改成同時把 `HTML_PATH` 與目錄列表寫進
log，讓未來除錯一眼看到實際解壓位置。

### 步驟 4：對 `webview.start()` 加 try/except，並把例外寫進 log

**檔案：[src/zen_type/settings_window.py:179](src/zen_type/settings_window.py)**

包一層 try/except 寫 `logger.exception("...")`。這樣即便是 WebView2 Runtime 缺
失或 GTK/CEF 後端問題，也不會 silent crash。如果 log 顯示 WebView2 相關錯誤，
最終可以在 README/build 文件提示「需安裝 Microsoft Edge WebView2 Runtime」，
或在 build 時加入 `--collect-binaries` 把 runtime 一起打包（pywebview 的 EdgeChromium
後端需要它）。

### 步驟 5：重 build & 驗證

依 README/build.py 流程重 build 一份 0.2.1：

1. `uv run python build.py --debug`
   - 用 `--debug` 含 console 的版本先跑一次，console 會直接顯示 stderr，
     對照 log 檔內容雙重確認失敗點。
2. 跑 `dist\zen-type-0.2.0.exe`（debug 版）→ 右鍵「開啟設定」
3. 看 console 與 `%APPDATA%\zen-type\zen-type.log`
4. 根據 log 對症處理：
   - 若是 HTML_PATH 找不到 → 步驟 3 已解；確認 `--add-data` 路徑是否正確
   - 若是 `webview.start()` throw → 確認是否需要 WebView2 Runtime；測試
     `webview.start(gui="cef")` 等 fallback
   - 若是 import error / hidden import 缺失 → 在 build.py 新增
     `--hidden-import` 或 `--collect-submodules`
5. 通過後 `uv run python build.py`（無 console）出最終版

## 驗證

1. 原始碼模式仍能開啟設定視窗：
   `uv run python -m zen_type.app`
2. 凍結 debug 模式（含 console）：`uv run python build.py --debug`，雙擊 exe，
   按右鍵 → 開啟設定 → 視窗出現；console 與 log 檔皆有 `[settings-child]`
   的 INFO 訊息。
3. 凍結 release 模式（無 console）：`uv run python build.py`，重複上一步；
   設定視窗應正常出現，log 檔同樣有完整紀錄。
4. 故意把 WebView2 Runtime 移除測試（可用乾淨的 VM 或停用 runtime）→ 確認
   現在會在 log 顯示明確錯誤而不是 silent。
